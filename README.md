When I first read both tasks in the assignment, I decided to prioritize the coding task over a research-heavy approach in order to manage my time efficiently. Since I already had prior knowledge of Python, I felt more confident implementing a system rather than focusing only on theoretical exploration. Therefore, I chose to work on Task 1, even though many of the core concepts such as Retrieval-Augmented Generation (RAG), FAISS, and Streamlit were completely new to me.

Before starting the implementation, I spent time learning these unfamiliar concepts. I referred to YouTube tutorials, explored the resources provided in the assignment, and used AI tools to understand what a RAG pipeline is and how such a system should be approached. This helped me build a basic conceptual understanding of how retrieval, context augmentation, and answer generation fit together in a real-world application.

Once I had a rough understanding of the pipeline, I began the implementation by importing all the necessary libraries such as pdfplumber, json, numpy, and sentence-transformers. The first major step was data cleaning. Using pdfplumber, I created a PDF object from The Odyssey and extracted text from all its pages. I stored this extracted content in a raw_text variable and then saved it into a raw text file using the write function.

After that, I opened the raw text file again, extracted all its contents, and split the text line by line into a list. I then applied preprocessing logic by looping over these lines and removing unnecessary content such as page numbers, very short lines, uppercase-only text, and Project Gutenberg boilerplate text. The remaining useful lines were then combined with proper spacing and saved into a clean text file, which served as the foundation for the next stages of the project.

The next step was chunk creation. In a separate file, I opened the clean text file and split its contents based on paragraph gaps. To attach meaningful metadata, I created variables to track the current book (chapter), paragraph range, and chunk ID. While looping through the split text, I checked whether a paragraph started with the word “BOOK” and, if so, updated the current chapter accordingly. I continuously added text to a current_chunk variable until its length crossed approximately 300 words. Once this threshold was reached, I created a chunk in dictionary format containing the chunk ID, text, chapter name, approximate paragraph range, and source reference. These chunks were stored in a list and finally saved in JSON format.

After chunking, I moved on to embedding generation. In another script, I loaded the chunk JSON file and initialized a SentenceTransformer model. I looped through each chunk and encoded its text into a vector embedding. These embeddings were normalized to improve similarity comparisons, based on guidance I received from AI tools during development. The embeddings were stored in a separate list, while metadata such as chunk ID, text, chapter, paragraph range, and source were saved into a metadata structure. The embeddings were then converted into a NumPy array and saved, along with the metadata, in JSON format.

Next, I implemented the FAISS indexing stage. To understand how to approach this, I again consulted AI tools and documentation. I loaded the embedding vectors, determined their dimensionality, and created a FAISS index object using this dimension. All embedding vectors were added to the index, and the final FAISS index was saved in .index format for later retrieval during question answering.

The final stage was implementing the Streamlit-based chatbot interface. Initially, I was unfamiliar with Streamlit and unsure how to design the question-answering workflow. After further learning and referring AI tools, I created a load_resources function to load the FAISS index, metadata, and embedding model only once. In the UI section, I used Streamlit functions to display the application title and provide a text input field for user questions.

When a user submits a question, the system first generates an embedding for the question, normalizes it, and converts it into the required array format. This embedding is then used to retrieve the most relevant chunks from the FAISS index. If no relevant chunks are found, an error message is displayed. Otherwise, the system extracts sentences from the retrieved chunks, filters out very short or irrelevant sentences, and computes cosine similarity between the question embedding and each sentence embedding. The sentence with the highest similarity score is selected as the final answer, provided it passes a relevance threshold. The answer is then displayed along with exactly two source references for clarity.

During development, I encountered several challenges. One recurring issue was that references from Book 9 appeared frequently, even though the paragraph ranges differed. This occurred due to semantic similarity rather than an actual error in indexing. Additionally, the paragraph ranges displayed are approximate and based on chunk segmentation rather than the original textbook paragraph numbering. Another limitation is that the system does not generate fully synthesized answers; instead, it extracts the most relevant sentence related to the question.

I attempted to integrate an LLM-based approach using OpenAI to generate more precise answers from the retrieved context, but this was ultimately unsuccessful due to API quota and configuration issues. As a result, I finalized the project using an extractive RAG approach, which still adheres strictly to the assignment requirement of answering questions only from the provided text.

Overall, this project gave me practical exposure to the complete RAG pipeline, including text preprocessing, chunking, embeddings, vector search using FAISS, and building an interactive UI. Despite the limitations, the final system successfully demonstrates a working RAG-based Q&A bot and reflects my learning journey throughout the assignment.
